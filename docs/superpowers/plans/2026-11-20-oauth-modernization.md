# OAuth client modernization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace retired Oltu with a maintained shared OAuth client, preserve configured provider/account behavior, reject failed exchanges and stale browser callbacks, and keep credentials out of logs.

**Architecture:** Nimbus handles authorization/token protocol messages and bounded HTTP exchanges behind one shared client. Browser and REST adapters retain their public routes and use the same identity/profile boundary. A per-session single-use flow ticket coordinates browser state and identity installation.

**Tech Stack:** Java21, Gradle8.14.7, Nimbus OAuth2/OIDC SDK11.39, PostgreSQL18, Solr10.1, Tomcat9/Struts1, existing JUnit/EasyMock, local JDK HttpServer fixtures and Node22 live checks.

**Spec:** docs/superpowers/specs/2026-11-20-oauth-modernization-design.md

## Global Constraints

- User authorized ordered implementation, commit/push to fork and Java21 next-major floor. Preserve existing endpoint names, result shapes and provider/account IDs. No mandatory browser cookie/state requirement for REST clients.
- Preserve runtime databases intermine-runtime-fixed/userprofile-runtime-fixed and task-owned Solr volume; never run local testmine/setup.sh. Stop task Tomcat before DB-backed JVM tests and run build roots sequentially.
- Pin Nimbus11.39; no Oltu classes in packaged WAR. Inspect transitive/optional dependencies and duplicate classes. Test-only dependencies may remain; do not bundle them in runtime.
- Browser state:32randombytes,provider+exactredirect binding,ten-minute expiry,atomic single claim. A successful identity change invalidates pending and claimed flows. Network exchanges happen outside session lock; ticket check/profile creation/completion coordinate under it.
- HTTP defaults:10000ms connect and read timeout, redirect following disabled. Preserve explicit BODY/QUERY,FORM/JSON,identity mapping and resource-auth settings. Resource body mode becomes formPOST because old GET silently dropped its body. Absent token_type is normalized explicitly to Bearer for compatibility; explicitly unsupported types fail.
- No code/clientsecret/accesstoken/authorizationheader/requestbody/rawproviderresponse in logs or returned failures. JSON REST failures use non-success status; preserve global JSONP structured-error HTTP200 contract.
- No remote-provider credential use or live remote logins. Fake provider tests use sentinel credentials and disposable unit profiles. Historical provider endpoints outside verified Google/GitHub defaults are preserved and documented as unverified.
- Inline implementation, one fresh whole-branch reviewer, one Important/Critical RED→GREEN fix pass, no re-review. Exact final-source hosted CI and Checkstyle before beta integration. Keep auth integration gate pending if it is still running when this branch starts.

## Review Focus

- A delayed OAuth response after a password login, new OAuth initiation or logout must not overwrite the newer browser identity.
- Configured endpoints with existing query strings and credentials/codes containing Unicode, spaces,plus,ampersand or quotes must preserve exact values without moving secrets to unintended locations.
- Empty/null/object identity IDs or provider errors inside HTTP200 bodies must never create/link an account; email must not select an existing identity.
- Exception handling, redirect responses and legacy QUERY modes must not reintroduce secret logging through WebService's status500 parameter dump or browser exception causes.
- Provider display names and preference keys/values containing HTML/quotes must remain data in authenticated pages; actual Struts/JSP rendering and API results must keep identity values unchanged.
