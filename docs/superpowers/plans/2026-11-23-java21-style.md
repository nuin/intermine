# Java 21 Checkstyle implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline. Existing authorization covers implementation and fork pushes.

**Goal:** Make the style gate accept Java 21 while retaining meaningful violations.
**Architecture:** One shared engine version and the existing project style policy;
standalone positive/negative Gradle fixtures protect the build contract.
**Tech Stack:** Java 21, Gradle 8.14.7, Checkstyle 14.4.0.
**Spec:** `docs/superpowers/specs/2026-11-23-java21-style-design.md`

## Global Constraints

- Preserve zero-warning enforcement and existing exclusions; no blanket suppressions.
- Preserve operator/runtime data and both BlueGenes workspaces.
- No application runtime dependency changes or Java syntax rewrites merely for style.

## Review Focus

- Syntax acceptance must not bypass actual rules; test negative inputs too.
- Missing Javadoc checks split across versions; retain package-scope enforcement.
- All build roots must use the same engine, including importer special cases.
- Tool/parser failure or absent reports must fail the gate.
- XML reports must remain compatible with hosted report parsing.
