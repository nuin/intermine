# Incremental OAuth client modernization design

## Intent and authorization

This is the fourth phase in the user's approved PostgreSQL → search → browser authentication → incremental framework/library modernization order. The user authorized implementation, commit and push to the fork, and explicitly chose Java21 for the next major release. Continue on an isolated OAuth branch from the fully tested auth source while its hosted checks run; finish and integrate the auth gate before integrating OAuth. This increment replaces the retired OAuth dependency and repairs its exchange boundary; Struts/Tiles/Jersey replacement remains a later project.

## Evidence and approaches

Apache Oltu retired in March2018 (https://attic.apache.org/projects/oltu.html). Five classes use its client/common types; the WAR requires both today. Browser and REST callbacks duplicate token and user-info exchange, log credentials/token material, and REST swallows exceptions into an apparent successful response. Browser state is neither consumed nor bound to the selected provider. The Google-only JWT decode supplies an unused migration mapping; authentication actually uses user-info.

Builder choice: Nimbus OAuth2/OIDC SDK11.39, verified Maven Central release metadata and primary documentation/source, behind shared exchange code. A hand-written complete protocol client would leave more maintenance/security work with this fork; adopting a whole web/security framework would require a much broader servlet/Jakarta migration. Nimbus is independent of the web framework and supports the Java21 baseline. Pin runtime dependencies and inspect the WAR for duplicate classes and optional crypto/XML dependencies.

## Required behavior

- Preserve browser and REST route names, result shapes and account identity keys. Browser success calls the already-tested LoginHandler.completeLogin; REST returns its existing temporary API credential and merges anonymous lists through the existing guard, without installing browser authentication.
- One shared client builds authorization URLs and performs code→access token→userinfo exchanges. Preserve explicit provider endpoint, scope, client ID/secret, BODY/QUERY token format, FORM/JSON response format, identity envelope/id/name/email mappings and header/queryparam/body resource authorization. Old Oltu ignores bodies on GET, so resource body mode is currently broken. Builder decision: make explicit resource body mode a form POST, document the change, and test its wire request. Invalid configuration fails explicitly.
- Own the existing11-provider fallback endpoint catalog instead of importing Oltu's enum. Preserve explicit overrides and historical fallback behavior unless a provider's primary docs justify a documented correction. Do not claim all remote providers were tested. Use official current Google token endpoint and GitHub POST token exchange only after verification. Historical Microsoft/other-provider account migrations are outside this increment and must be documented, not silently remapped to new identity IDs.
- Browser initiation stores a fresh unpredictable state with provider, exact redirect URI and a ten-minute expiration in the session. Callback validates and atomically consumes the pending state before outbound calls or account lookup. Reject missing, expired, mismatched-provider, mismatched-state and replayed callbacks. No implicit fallback to unsigned/uncorrelated identity. A new successful browser identity invalidates both pending and already-claimed flows. Builder decision: retain a per-flow ticket after atomically claiming its state; verify that ticket under the session lock immediately before installing the OAuth identity. Coordinate all successful browser completions under the same session lock and invalidate the ticket there. Thus a delayed provider response cannot overwrite a newer password/OAuth login. Do outbound network calls outside the session lock. Add a deterministic concurrent account-switch regression using a blocked fake-provider response.
- REST authorization currently returns a link without redirect_uri or state; external clients provide those and send provider+redirect_uri+code to callback. Preserve that public contract, documenting client responsibility for state/redirect correlation. Do not add a mandatory session cookie or browser state requirement to REST. PKCE or OIDC ID-token login is not introduced silently.
- Bound connect/read waits; do not follow redirects carrying credentials or bearer tokens. Reject token/userinfo non-success HTTP status, provider error payload, missing/blank token, malformed payload and missing/blank/null identity ID. Keep provider ID authoritative; email never selects or links a local account. Existing aliases/preferences may be shared in a small profile helper if it removes browser/REST duplication without changing identity selection.
- Remove unused Google migration JWT decoding. Obtain identity from the configured userinfo endpoint; do not use unverified JWT claims as authentication evidence. Keep legacy migration classes only if other real consumers need them.
- Escape identity-derived message arguments and preference input keys/values in manageApiKey.jsp. The browser-auth reviewer found these adjacent string-to-markup paths; cover quoted/markup provider names and preference values. Generic rich-HTML flash message contracts elsewhere remain a documented separate audit.
- No code, client secret, access token, authorization header, token request body, or raw provider response in logs or returned error messages. Expected exchange failures produce a sanitized browser login error / non-success REST status. Preserve diagnosable phase/status information without sensitive payloads. WebService.getTruncatedStackTrace recursively prints cause.toString even for non500 statuses: REST adapters must construct sanitized ServiceExceptions WITHOUT the raw cause; browser adapters must not log the exchange exception/cause. The shared client can retain an internal cause for tests/debugging but it must never cross these public logging boundaries.
- For legacy responses with no token_type, explicitly normalize to Bearer because existing InterMine only used bearer resource requests; reject any explicitly unsupported token type. Keep custom QUERY token/resource modes available for compatibility and document their exposure in URL logs; prefer BODY/header defaults only where verified. No live remote login or use of real provider credentials in tests.

## Verification

Observe baseline failure before each production fix. Use a local fake HTTP OAuth provider with deterministic tokens/identities and request capture; exercise successful browser and REST paths, failure status handling, state replay/provider substitution/expiry, quoted/Unicode form values, FORM and JSON responses, token and resource placement, redirects/timeouts, malformed and blank identity data, and absence of secret sentinels from captured logs/errors. Assertions target wire requests and externally visible authentication/results, not merely helper internals. Keep tests bounded and deterministic; mock administrative mutations only. New browser completion tests may use real test API plus servlet mocks; REST tests should use its actual public process boundary where practical. Add at least a live negative REST callback check so swallowed errors cannot pass runtime validation.

Run focused tests/Checkstyle, full core build/install, generated testmine WAR validation, all persisted auth/search/registration live checks, JS/PY client suites, exact saved-list snapshot, Aislop and fresh final-source hosted CI. A separate fresh whole-branch reviewer is required once implementation tasks complete. One Important/Critical fix pass, no re-review. Preserve task-owned DB/Solr volumes and runtime fixture pair.

## Builder decisions still allowed

Exact class boundaries and typed exception names; a minimal fake-provider fixture and timeout-injection seam; whether a shared profile-preference helper is worthwhile; how to normalize FORM into the Nimbus response model without inventing authentication semantics. Keep public custom configuration behavior explicit, reject missing identity rather than synthesizing it, and document any unavoidable Java API constructor changes when removing Oltu types in this major release.
